Architecture

One settlement contract, two claim sources, a linear off-chain brain, and a read API that never waits on an LLM. Every write is idempotent. Every served state is re-derivable from public logs plus a hash preimage.

Sepolia settlement Sepolia + Unichain + extra Superchain L2s GET < 500ms commit < 2 min

Context

Actors: a holder (subject), any number of issuers, a relying party, and the Synapse operator key that is allowed to commit fused state. The operator is a hackathon concession: the scoring brain is off-chain. Integrity comes from the public preimage + hash, not from pretending the operator does not exist. Anyone can re-run the open pipeline on the same logs and check the hash.

Runtime pipeline

  1. Post. Demo script calls ClaimSource.postClaim on both chains with EIP-712 typed data or a simplified (subject, topic, polarity, expiresAt, evidenceURI) tuple. Polarity is +1 support / −1 contradict for a named topic.
  2. Watch. Ingest decodes logs. Cursor is (chainId, lastBlock). Restart is idempotent because claimIds are deterministic.
  3. Normalize. Gen-AI maps free-text evidenceURI bodies (or inline JSON) into NormalizedClaim. Schema in SCHEMA.html. On LLM failure, rules parser requires the inline JSON shape.
  4. Feature. Build the vector in SCHEMA.html: issuer beta mean, hours-to-expiry, revoked, signature-valid, confirmations, topic-conflict-count, chain-finality proxy, claim-age, issuer-volume.
  5. Score. model.predict_proba → p_i. Also keep the raw vector for SHAP.
  6. Opinion. Convert (p_i, evidence mass, issuer prior) to ω_i = (b, d, u, a). See MATH.html.
  7. Fuse. Group by topic. Cumulative fuse independent issuers. Average fuse obvious duplicates (same issuer, two chains, same payload). Cross-topic: produce a vector of topic verdicts plus a scalar confidence.
  8. Revise. If pairwise conflict K > θ, discount the weaker issuer (Jøsang 2017 trust revision) and refuse to hide the conflict in the JSON.
  9. Commit. If commitId is new, send IdentityState.commit. Wait for 1 confirmation. Store receipt.
  10. Serve. GET /v1/identity is overlay JSON (mtime cache). No LLM and no live RPC on that path. pendingOnChain stays true on a writer-less host until Sepolia latest() already stores the same commitId / stateHash (laptop scripts/commit_overlay.py if a new fuse reminted the clock). History is a separate 15s-cached eth_call.
  11. Explain. Built asynchronously after score. Never on the GET hot path. Cached next to the commit.

Contracts

ClaimSource.sol (deployed twice)

/// @notice Minimal claim bulletin board. Not an IdP.
interface IClaimSource {
    event ClaimPosted(
        bytes32 indexed claimId,
        address indexed subject,
        address indexed issuer,
        bytes32 topic,
        int8 polarity,
        uint64 expiresAt,
        string evidenceURI
    );
    event ClaimRevoked(bytes32 indexed claimId, address indexed issuer, uint64 at);

    function postClaim(
        address subject,
        bytes32 topic,
        int8 polarity,
        uint64 expiresAt,
        string calldata evidenceURI
    ) external returns (bytes32 claimId);

    function revokeClaim(bytes32 claimId) external;

    function claimIdOf(
        address subject,
        address issuer,
        bytes32 topic,
        int8 polarity,
        uint64 expiresAt,
        string calldata evidenceURI
    ) external pure returns (bytes32);
}

claimId = keccak256(abi.encode(chainid, subject, issuer, topic, polarity, expiresAt, evidenceURI)). msg.sender is the issuer. Revoke only by issuer. Do not store the URI string in an expensive way if gas hurts — emit it and keep exists/revoked/expiresAt in a packed struct.

IdentityState.sol (Sepolia)

interface IIdentityState {
    event StateCommitted(
        bytes32 indexed commitId,
        address indexed subject,
        bytes32 stateHash,
        uint16 scoreBps,
        bytes32 modelVersion,
        uint64 issuedAt
    );

    function commit(
        address subject,
        bytes32 commitId,
        bytes32 stateHash,
        uint16 scoreBps,
        bytes32 modelVersion
    ) external;

    function latest(address subject) external view returns (
        bytes32 commitId,
        bytes32 stateHash,
        uint16 scoreBps,
        bytes32 modelVersion,
        uint64 issuedAt,
        uint64 blockNumber
    );
}
  • Only operator (constructor) may commit. Document the operator key.
  • commit reverts if commitId already used (or returns silently — pick one and test it). Prefer revert-on-duplicate for honesty, catch in the writer.
  • scoreBps is 0–10000. 10000 = certainty.
  • No upgradeability in 6 hours. Immutability is the point.
  • Use OpenZeppelin Ownable for the operator. Do not pull in governor or UUPS.

What we do not deploy

No ERC-725 identity proxy per user. No ERC-735 claim holder as a dependency (we can echo its claim-id idea). No ERC-8004 registries as a hard dep. No CCIP receiver. Optional later: store stateHash preimage CID via a string event. On the cloud side: no RDS, no NAT, no ALB, no always-on App Runner unless a human flipped enable_runtime in DEVOPS.html. Vercel hosts the Vite dashboard only.

Identity format

Internally we speak NormalizedClaim. On the wire, prefer a W3C VC 2.0-shaped JSON so judges see standards literacy:

  • Subject and issuer as did:ethr:sepolia:0x… on settlement and did:ethr:eip155:{chainId}:0x… on extra L2s (Unichain 1301, Base 84532, OP 11155420, Ink 763373, Mode 919, Soneium Minato 1946) using uport-project/ethr-did conventions and ERC-1056 semantics. You do not have to deploy EthereumDIDRegistry for the MVP; treat the address as the DID method-specific-id. Unknown chain IDs raise.
  • Revocation: if clock allows, a bit on ClaimSource is enough. Mention Bitstring Status List (W3C) as the production analogue. Do not implement gzip bitstrings in 6 hours unless you are ahead.
  • Hash-only on-chain payload follows the 2025 heterogeneous-chain VC paper: anchoring hashes, not full credentials, cuts gas ~85%.

Determinism and idempotency

  • claimId and commitId are pure functions of public fields.
  • sklearn model is frozen at modelVersion = keccak256(file bytes).
  • Fusion is pure. Same claims + same model → same scoreBps. Float to bps via round(10000 * P) with half-up documented.
  • Writer uses a mutex per subject so two watchers cannot double-send.
  • If a tx is dropped, resend the exact same calldata.

Trust boundary

Trusted for liveness

Operator key, RPC providers, the LLM endpoint, the machine running ingest. If they die, reads still serve last commit.

Trusted for integrity

None, if the relying party re-runs the open pipeline. The hash is a commitment, not a proof of honest scoring. Publish the model file hash on-chain via modelVersion.

This is honest decentralization for a 6-hour build. Do not claim zkML. ERC-8004-style validation registries and zk proofs are research follow-ons (RESEARCH.html).

ML subsystem

Training is offline, before or at the start of the hackathon clock. Generate ≥ 800 labeled rows. Labels are functions of hidden ground-truth plus noise, not of the features themselves in a trivial copy (do not make revoked=1 ⇒ label=0 the only rule — include issuer fraud, expiry-near, and cross-chain conflicts). Hold out 20%. Target accuracy > 75% is easy if you are not sloppy; also report F1 so a 90/10 class split cannot cheat.

Model choice: HistGradientBoostingClassifier(max_depth=3, max_iter=80). Fast, SHAP-friendly via TreeExplainer. LogisticRegression is the fallback if shap/trees eat the clock — LinearExplainer then.

Hugging Face: optional encoder for evidence text (sentence-transformers/all-MiniLM-L6-v2) as extra features. Only if CPU inference stays < 50 ms per claim. Do not download a 7B model.

Gen-AI subsystem

Two orchestrated prompts, both structured:

  1. Extract. Claim text → NormalizedClaim. Temperature 0. Tools: none.
  2. Explain. Inputs: fused state, per-claim p_i, SHAP top features, conflict list. Output: {summary, reasons[], caveats[]}. Temperature 0.2.

Optional third: CRAVE-style dual perspective (“why this claim is true” / “why false”) then a non-fine-tuned synthesis. See PROMPTS.html. Orchestration runner: Instructor over LiteLLM (verified 567-labs/instructor, BerriAI/litellm). DSPy (stanfordnlp/dspy) remains an allowed alternative. Compozy is for the human team’s agents, not a runtime dep of the API. Env LLM_* is the operator default for ingest. Browser BYOK is localStorage + per-request; keys are never written to disk, overlay, or explanation JSON. GET identity never calls the LLM. The official score is still sklearn + Jøsang — the LLM does not emit scoreBps / pCredible.

Dashboard (bonus)

Three panes: timeline of claims (chain badges), fusion inspector (opinions as stacked b/d/u), commit rail (tx hash, score sparkline). Poll GET every 2s. Empty/error/loading states required. Tokens in DESIGN.html.

Security notes (testnet, still real)

  • Issuer is msg.sender. Do not let the subject spoof issuer.
  • evidenceURI is untrusted. Never fetch it in a way that can SSRF into cloud metadata. Allow only ipfs://, https:// to a demo host, or inline data:application/json.
  • Cap URI length. Cap explanation size.
  • Operator key on a fresh throwaway account. Faucet only.
  • No delegatecall, no upgrade proxy, no tx.origin.
  • Integer score in bps; never send floats on-chain.

Revoke path (bonus B-01, still designed in)

Issuer calls revokeClaim. Watcher sees ClaimRevoked, sets revoked=true, forces p_i ← min(p_i, 0.05) and adds disbelief mass. Fusion re-runs. New commitId (claimsRoot is unchanged — same claim set — but scoreBps moves, and scoreBps is in the commitId preimage precisely so this case gets a distinct id). GET history shows both commits. Do not delete the old log.

Clock trade-offs (what we cut, what we never cut)

PLAN.html is the schedule. If late, cut in this order: dashboard → MiniLM embeddings → CRAVE dual-perspective prompt → LLM extract (keep the prompt file, use rules). Never cut: two-chain ingest, sklearn score, on-chain commit, GET JSON, held-out accuracy print, one explanation even if templated from SHAP + fusion numbers.

Known 6-hour concessions, said out loud: the operator key can commit; the LLM is optional; labels are synthetic; two EVM testnets are not “every chain”; the hash is a commitment, not a zk proof of honest scoring.

Assumptions, limitations, gaps

  • Issuers are addresses. Anyone may post. We score them with a Beta prior; we do not onboard them as an IdP.
  • Topics are closed. Demo topics are kyc.adult, kyc.active, optional residency.eu. Open-ended natural-language identity is out of scope.
  • Polarity is binary. +1 / −1 on a named proposition. Multi-class “residency = FR vs DE vs unknown” would need Dirichlet reputation — refused on the clock.
  • Evidence is not PII. evidenceURI is demo JSON or a capped URL. No government-ID images. Append-only ledgers cannot honor GDPR deletion.
  • Finality is a proxy. confirmations_norm is not economic finality. Reorg rewind is N=12 on every cataloged chain.
  • Model generalization is unproven off the synthetic set. Accuracy > 75% is on a held-out slice of data we generated. Production would need labeled real claims and a model card.
  • Integrity is reproducible, not trustless execution. A relying party who re-runs the open pipeline and checks stateHash does not need to trust our API host. They still trust that our published model file is the one we used — that is what modelVersion is for.

Scalability (honest)

  • Read path is cheap: overlay JSON (mtime) on GET identity; history may one eth_call if cache age > 15s. NFR-01 is a warm local scripts/nfr01_load.sh (hey -n 200 -c 20) — not India→us-east-1 App Runner RTT.
  • Write path is per-subject, not global. A mutex per subject prevents double-send. Many subjects interleave.
  • Bottlenecks are public RPC rate limits and settlement gas, not fusion arithmetic (O(n) claims per subject, n is tiny in the demo).
  • Watchers scale by chain. Cold ingest for the FR-01 pair starts at each ClaimSource deploy block (chunked 2k logs). Extra L2s use a recent window on first pass so seven full scans do not starve GET. Do not claim “millions of QPS.”
  • Explain is async and cache-keyed by commitId so it cannot take the read path down.
  • What would break first in production: one operator key, one RPC URL, one host for ingest+writer, synthetic labels. Mitigations are in the production section, not in the 6-hour binary.

Deploy, maintain, support (after the clock)

The 6-hour artifact is a testnet demo. This is the path we would take if it had to live:

  1. Deploy. Foundry scripts already reject chain id 1 and 137. Pin solc 0.8.24. Verify IdentityState on Etherscan. Publish addresses, modelVersion, and the preimage schema in the README. Hosted UI + gated AWS: DEVOPS.html — Vercel Hobby for dashboard/, OIDC+ECR only until a human pays for compute.
  2. Release. Tag the git SHA that produced model.joblib. New model ⇒ new modelVersion ⇒ new commits; do not rewrite history.
  3. Run. Two processes: ingest+writer, API. Overlay via os.replace on data/overlay.json. Systemd or a compose file with healthcheck on /v1/health.
  4. Keys. Throwaway faucet key for the demo. Production: operator behind a 2-of-3 multisig or a timelock; never a funded mainnet key in env on a laptop.
  5. RPC. At least two URLs per chain. Fail over on 429/5xx. Document rate limits.
  6. Support. Replay POST /v1/replay/{subject} reconstructs state from logs. scripts/verify_hash.py is the customer-facing “did you cheat?” tool. Incident playbook: if any extra L2 dies, serve Sepolia + last snapshot for that chainId with degradedChains; do not invent claims. If Unichain stays down, prefer another watched Superchain L2; scripts/emergency_anvil_source.sh is the last-resort live second source — flagged via emergencySource, never presented as real Unichain. Do not silently revert to Amoy.
  7. Change control. No upgrade proxy on IdentityState. A new contract is a new deployment and a documented cutover. ClaimSource can be redeployed per chain; watchers pick up addresses from env.

What we would build next

  • Bitstring Status List as the production revocation analogue (MVP keeps an on-chain bit).
  • EIP-712 typed claims so issuers are not only msg.sender on our bulletin board.
  • Issuer–issuer EigenTrust once we have more than a handful of issuers.
  • MiniLM evidence embeddings if CPU stays < 50 ms/claim.
  • Optional ACE-style minValidations as an input feature (corroboration count), not a wrap of Chainlink.
  • Model card, calibration plot, and a real labeled set.
  • ERC-8004 footnote only if we later publish the explainer as an agent — not the product.

Must not become the runtime (RESEARCH.html): Passport/Trusta APIs, CCIP/LayerZero identity bridges, ION/Ceramic/ACA-Py, STARK circuits, fine-tuned judges.

Why this is not overbuilt

A 6-hour architecture that includes zk-STARKs, a bidirectional Geth–Besu bridge, Ceramic, and a Dirichlet reputation DHT will not demo. Those papers inform the math and the story (RESEARCH.html). The running system is two contracts, one Python service, one model file, one API.
