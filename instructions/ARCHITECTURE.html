Architecture

One settlement contract, two claim sources, a linear off-chain brain, and a read API that never waits on an LLM. Every write is idempotent. Every served state is re-derivable from public logs plus a hash preimage.

Sepolia settlement Sepolia + Amoy sources GET < 500ms commit < 2 min

Context

Actors: a holder (subject), any number of issuers, a relying party, and the Synapse operator key that is allowed to commit fused state. The operator is a hackathon concession: the scoring brain is off-chain. Integrity comes from the public preimage + hash, not from pretending the operator does not exist. Anyone can re-run the open pipeline on the same logs and check the hash.

Runtime pipeline

  1. Post. Demo script calls ClaimSource.postClaim on both chains with EIP-712 typed data or a simplified (subject, topic, polarity, expiresAt, evidenceURI) tuple. Polarity is +1 support / −1 contradict for a named topic.
  2. Watch. Ingest decodes logs. Cursor is (chainId, lastBlock). Restart is idempotent because claimIds are deterministic.
  3. Normalize. Gen-AI maps free-text evidenceURI bodies (or inline JSON) into NormalizedClaim. Schema in SCHEMA.html. On LLM failure, rules parser requires the inline JSON shape.
  4. Feature. Build the vector in SCHEMA.html: issuer beta mean, hours-to-expiry, revoked, signature-valid, confirmations, topic-conflict-count, chain-finality proxy, claim-age, issuer-volume.
  5. Score. model.predict_proba → p_i. Also keep the raw vector for SHAP.
  6. Opinion. Convert (p_i, evidence mass, issuer prior) to ω_i = (b, d, u, a). See MATH.html.
  7. Fuse. Group by topic. Cumulative fuse independent issuers. Average fuse obvious duplicates (same issuer, two chains, same payload). Cross-topic: produce a vector of topic verdicts plus a scalar confidence.
  8. Revise. If pairwise conflict K > θ, discount the weaker issuer (Jøsang 2017 trust revision) and refuse to hide the conflict in the JSON.
  9. Commit. If commitId is new, send IdentityState.commit. Wait for 1 confirmation. Store receipt.
  10. Serve. API returns overlay (memory) if newer than last commit, flagged pendingOnChain: true, plus the last finalized commit.
  11. Explain. Built asynchronously after score. Never on the GET hot path. Cached next to the commit.

Contracts

ClaimSource.sol (deployed twice)

/// @notice Minimal claim bulletin board. Not an IdP.
interface IClaimSource {
    event ClaimPosted(
        bytes32 indexed claimId,
        address indexed subject,
        address indexed issuer,
        bytes32 topic,
        int8 polarity,
        uint64 expiresAt,
        string evidenceURI
    );
    event ClaimRevoked(bytes32 indexed claimId, address indexed issuer, uint64 at);

    function postClaim(
        address subject,
        bytes32 topic,
        int8 polarity,
        uint64 expiresAt,
        string calldata evidenceURI
    ) external returns (bytes32 claimId);

    function revokeClaim(bytes32 claimId) external;

    function claimIdOf(
        address subject,
        address issuer,
        bytes32 topic,
        int8 polarity,
        uint64 expiresAt,
        string calldata evidenceURI
    ) external pure returns (bytes32);
}

claimId = keccak256(abi.encode(chainid, subject, issuer, topic, polarity, expiresAt, evidenceURI)). msg.sender is the issuer. Revoke only by issuer. Do not store the URI string in an expensive way if gas hurts — emit it and keep exists/revoked/expiresAt in a packed struct.

IdentityState.sol (Sepolia)

interface IIdentityState {
    event StateCommitted(
        bytes32 indexed commitId,
        address indexed subject,
        bytes32 stateHash,
        uint16 scoreBps,
        bytes32 modelVersion,
        uint64 issuedAt
    );

    function commit(
        address subject,
        bytes32 commitId,
        bytes32 stateHash,
        uint16 scoreBps,
        bytes32 modelVersion
    ) external;

    function latest(address subject) external view returns (
        bytes32 commitId,
        bytes32 stateHash,
        uint16 scoreBps,
        bytes32 modelVersion,
        uint64 issuedAt,
        uint64 blockNumber
    );
}
  • Only operator (constructor) may commit. Document the operator key.
  • commit reverts if commitId already used (or returns silently — pick one and test it). Prefer revert-on-duplicate for honesty, catch in the writer.
  • scoreBps is 0–10000. 10000 = certainty.
  • No upgradeability in 6 hours. Immutability is the point.
  • Use OpenZeppelin Ownable for the operator. Do not pull in governor or UUPS.

What we do not deploy

No ERC-725 identity proxy per user. No ERC-735 claim holder as a dependency (we can echo its claim-id idea). No ERC-8004 registries as a hard dep. No CCIP receiver. Optional later: store stateHash preimage CID via a string event.

Identity format

Internally we speak NormalizedClaim. On the wire, prefer a W3C VC 2.0-shaped JSON so judges see standards literacy:

  • Subject and issuer as did:ethr:sepolia:0x… / did:ethr:polygon:amoy:0x… using uport-project/ethr-did conventions and ERC-1056 semantics. You do not have to deploy EthereumDIDRegistry for the MVP; treat the address as the DID method-specific-id.
  • Revocation: if clock allows, a bit on ClaimSource is enough. Mention Bitstring Status List (W3C) as the production analogue. Do not implement gzip bitstrings in 6 hours unless you are ahead.
  • Hash-only on-chain payload follows the 2025 heterogeneous-chain VC paper: anchoring hashes, not full credentials, cuts gas ~85%.

Determinism and idempotency

  • claimId and commitId are pure functions of public fields.
  • sklearn model is frozen at modelVersion = keccak256(file bytes).
  • Fusion is pure. Same claims + same model → same scoreBps. Float to bps via round(10000 * P) with half-up documented.
  • Writer uses a mutex per subject so two watchers cannot double-send.
  • If a tx is dropped, resend the exact same calldata.

Trust boundary

Trusted for liveness

Operator key, RPC providers, the LLM endpoint, the machine running ingest. If they die, reads still serve last commit.

Trusted for integrity

None, if the relying party re-runs the open pipeline. The hash is a commitment, not a proof of honest scoring. Publish the model file hash on-chain via modelVersion.

This is honest decentralization for a 6-hour build. Do not claim zkML. ERC-8004-style validation registries and zk proofs are research follow-ons (RESEARCH.html).

ML subsystem

Training is offline, before or at the start of the hackathon clock. Generate ≥ 800 labeled rows. Labels are functions of hidden ground-truth plus noise, not of the features themselves in a trivial copy (do not make revoked=1 ⇒ label=0 the only rule — include issuer fraud, expiry-near, and cross-chain conflicts). Hold out 20%. Target accuracy > 75% is easy if you are not sloppy; also report F1 so a 90/10 class split cannot cheat.

Model choice: HistGradientBoostingClassifier(max_depth=3, max_iter=80). Fast, SHAP-friendly via TreeExplainer. LogisticRegression is the fallback if shap/trees eat the clock — LinearExplainer then.

Hugging Face: optional encoder for evidence text (sentence-transformers/all-MiniLM-L6-v2) as extra features. Only if CPU inference stays < 50 ms per claim. Do not download a 7B model.

Gen-AI subsystem

Two orchestrated prompts, both structured:

  1. Extract. Claim text → NormalizedClaim. Temperature 0. Tools: none.
  2. Explain. Inputs: fused state, per-claim p_i, SHAP top features, conflict list. Output: {summary, reasons[], caveats[]}. Temperature 0.2.

Optional third: CRAVE-style dual perspective (“why this claim is true” / “why false”) then a non-fine-tuned synthesis. See PROMPTS.html. Orchestration runners: Instructor (verified 567-labs/instructor), DSPy (stanfordnlp/dspy), or Compozy for multi-agent coding (compozy/compozy) — Compozy is for the human team’s agents, not a runtime dep of the API.

Dashboard (bonus)

Three panes: timeline of claims (chain badges), fusion inspector (opinions as stacked b/d/u), commit rail (tx hash, score sparkline). Poll GET every 2s. Empty/error/loading states required. Tokens in DESIGN.html.

Security notes (testnet, still real)

  • Issuer is msg.sender. Do not let the subject spoof issuer.
  • evidenceURI is untrusted. Never fetch it in a way that can SSRF into cloud metadata. Allow only ipfs://, https:// to a demo host, or inline data:application/json.
  • Cap URI length. Cap explanation size.
  • Operator key on a fresh throwaway account. Faucet only.
  • No delegatecall, no upgrade proxy, no tx.origin.
  • Integer score in bps; never send floats on-chain.

Why this is not overbuilt

A 6-hour architecture that includes zk-STARKs, a bidirectional Geth–Besu bridge, Ceramic, and a Dirichlet reputation DHT will not demo. Those papers inform the math and the story (RESEARCH.html). The running system is two contracts, one Python service, one model file, one API.
