Visual system · dashboard · explanation UX

Design

The product should feel like a watch floor for identity evidence, not a consumer fintech card grid and not a neon “AI brain.” These tokens are already used by this dossier (instructions/docs-assets/synapse.css). Reuse them in the dashboard.

Direction

Workstation-dense, warm ink. Bone type on near-black, oxidized copper for signal, moss for “settled / ok,” brick for conflict. Serif headlines (Newsreader), IBM Plex Sans for UI, IBM Plex Mono for hashes and scores. Plenty of air in the dossier; tighter density in the live dashboard.

Forbidden defaults: Inter, purple-to-blue gradients, glassmorphism, 3D orbs, “neural” backgrounds, rainbow chain badges, rounded-everything, generic shadcn themes without retokenizing, stock Unsplash heroes, “Unlock the future of identity” copy.

Focus ring: 2px solid var(--copper) offset 2px. Do not remove outlines. Hit targets ≥ 40×40 on the subject search and retry buttons. Respect prefers-reduced-motion — no continuous pulse on “live.”

Type

  • Headlines: Newsreader, 500, tracking −0.03em.
  • UI: IBM Plex Sans, 14–16px, line-height 1.5.
  • Hashes, bps, chainIds: IBM Plex Mono, 12–13px. Truncate 0x + 6 + … + 4 with a copy button (real <button>).

Dashboard architecture

One route: /#/{subject}. Query string also fine. Three columns on desktop, stacked on 375px:

  1. Rail. Subject input, health chips (Sepolia, Unichain, Base, OP, Ink, Mode, Minato heads + accuracy), last commit hash → explorer.
  2. Claims. Chronological list. Each row: chain chip, issuer, topic, polarity, pCredible, revoked/expired marks. Opposite polarities on the same topic get a shared brick rule.
  3. Fusion. For each topic, a stacked bar of b / d / u (copper / brick / mute). Confidence as a single large mono number, not a speedometer.

Explanation sits under fusion: summary, then reasons as a definition list (feature · shap · sentence). Caveats in mute. A LiteLLM / BYOK panel (API key as password, base URL, model) persists only in localStorage, exposes Test connection and Generate explanation, and never puts the key on GET polls. Chip the health llm.envConfigured flag and last explanation.engine.

Copy

  • “Conflict on kyc.adult” not “We detected an anomaly in your identity graph.”
  • “Commit 0xabc… · 4100 bps” not “Successfully anchored your trust crystal.”
  • “Issuer prior 0.18 (hostile seed)” not “Low vibe score.”
  • Buttons: “Replay from logs”, “Copy hash”, “Open Sepolia tx”, “LiteLLM / BYOK”, “Test connection”, “Generate explanation.”

Motion

150–200ms ease-out on hover and expand. New claims may briefly highlight the row once. No layout thrash: skeletons reserve space. If reduced motion, highlights are static chips.

Accessibility

  • Real buttons and links. Label the subject field.
  • Contrast: bone on ink passes; mute on ink is for non-essential meta only.
  • Do not encode verdict only in color — include the word.
  • Explorer links have discernible text, not icon-only without aria-label.

API as a designed surface

Pretty-print JSON in the video with jq. Field order as SCHEMA.html. Humans read verdict, confidence, conflicts first — keep those keys at the top.

Mark

The ◎ copper ring in the dossier mast is the only logo. Do not add a brain-plus-chain illustration. If you need a favicon, it is that ring on ink.
