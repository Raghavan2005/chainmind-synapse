HTML is the spec, not Markdown

Long Markdown plans are how humans check out of the loop. Thariq Shihipar (Claude Code) and the June 2026 InfoQ write-up argue that HTML — color, in-page nav, tailored layout — keeps a human engaged while the agent works. We follow that here.

  • Treat every file in instructions/ as the living spec. Update the HTML when a decision changes. Do not spawn a parallel PLAN.md, ARCHITECTURE.md, or docs/*.md.
  • When you report status to a human, prefer a short note plus a link/path to the relevant HTML section over a 200-line Markdown dump.
  • Repo-root AGENTS.md and CLAUDE.md are pointers only. This file wins on conflict.

Sources: InfoQ — HTML increasingly better than Markdown in agentic loops (24 Jun 2026); Shihipar, Using Claude Code: The Unreasonable Effectiveness of HTML.

You must

  • Keep every blockchain write idempotent. Same commitId → no-op, same logs.
  • Keep the GET path free of LLM calls and free of “wait for receipt.”
  • Train the model on a checked-in synthetic dataset so the demo is reproducible without a GPU.
  • Print held-out accuracy in the README and in the API GET /v1/health.
  • Store stateHash = keccak256(abi.encode(subject, claimsRoot, scoreBps, modelVersion, issuedAt)) and publish the preimage JSON so third parties can verify.
  • Engineer at least one conflicting-claim fixture for the demo subject.
  • Cite SHAP feature names in the explanation JSON, not only in prose.
  • Use public RPCs if no key exists: https://rpc.sepolia.org and https://rpc-amoy.polygon.technology/. Document that they rate-limit.
  • After code changes, run graphify update . if graphify is installed.
  • Verify the API with curl. Verify the dashboard in a browser if you touch UI.

You must not

  • Fine-tune, LoRA, or DPO any model.
  • Call Trusta, Nomis, RubyScore, Ethos, Cred Protocol, UTU, Gitcoin Passport, Worldcoin, or Civic to produce scores.
  • Depend on Chainlink CCIP or LayerZero for the MVP (plumbing, not required, clock killer).
  • Put private keys in git. .env is gitignored. .env.example has blanks.
  • Use a funded mainnet key. Ever.
  • Invent GitHub repos. If it is not in REPOS.html, run gh repo view owner/name before telling a human to clone it.
  • Swallow RPC errors. Surface them on /v1/health.
  • Write a dashboard that is the only way to see the score. The API is the product.
  • Commit node_modules, Foundry cache/, out/, or model weights larger than needed. model.joblib for a tiny sklearn model is fine.
  • Claim “decentralized” while the only copy of the explanation lives in a closed vendor dashboard.

If LLM_API_KEY is missing, the extractor falls back to a deterministic rules parser so the demo still runs. The Gen-AI explanation then uses a template filled with SHAP + fusion numbers. Say this in the demo if it happens.

Quality bar under a 6-hour clock

  • Forge tests for commit idempotency, hash matching, and revoke → rescore.
  • pytest for fusion operators (compare against the formulas in MATH.html) and for API schema.
  • One happy-path script: scripts/demo_flow.sh posts two conflicting claims, waits for commit, curls the API, prints the tx.
  • No unused abstraction layers. Three Solidity contracts max (ClaimSource, IdentityState, maybe a shared interface file).

Voice in code and UI

Write comments that explain invariants, not narration. UI copy is short and specific: “Two claims disagree on majority” not “There is currently a discrepancy in the identity graph.” Design tokens are copper / bone / moss on ink. See DESIGN.html.

When stuck

  1. Cut bonus, not MVP.
  2. Replace the LLM extractor with the rules fallback; keep the prompt file for the demo narration.
  3. If Amoy RPC dies, still ingest Sepolia and a second source via a locally deployed Anvil chain documented as the emergency second source, then retry Amoy. The PRD wants two blockchains, not two happy RPCs.
  4. If Foundry cannot install, use the Hardhat fallback in SKILL.html.

Definition of done

A stranger can run the bootstrap in REPOS.html + INTEGRATION.html, deploy with the Foundry script, run scripts/demo_flow.sh, and get a JSON identity state plus a block explorer link. Accuracy script prints > 75%. You have a 3-minute recording script from PLAN.html. You did not add a hosted database or a commercial identity SDK.
