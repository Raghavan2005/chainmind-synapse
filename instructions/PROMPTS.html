Prompt orchestration

Two production prompts and one optional CRAVE-style pair. Temperature is specified. Outputs are pydantic models via Instructor over LiteLLM. If the model rambles, Instructor/Outlines reject and you retry once, then fall back.

Orchestration rules

  • Prompts live in services/normalize/prompts/ and services/explain/prompts/ as text files. Do not bury them in code.
  • Calls go through LiteLLM (instructor.from_litellm(litellm.completion)). Env LLM_* is the operator default; browser BYOK is per-request only.
  • No tool-calling to the internet from the extractor. The evidence body is already fetched (safely) or inline.
  • Never ask the LLM for scoreBps or pCredible.
  • Log prompt version = sha256 of the file. Put it in explanation JSON as promptVersion if easy.
  • DSPy: signatures only, no BootstrapFewShot that writes weights if that worries the PRD. Static demos in the prompt are allowed (that is prompt engineering).

P1 — Extract NormalizedClaim

System:

You are a clerk, not a judge. Extract fields from an on-chain identity claim.
Do not decide if the claim is true. Do not invent issuers or dates.
If a field is missing, use the schema default or null.
Polarity is +1 if the evidence supports the topic proposition, -1 if it denies it.
Topic must be one of: kyc.adult, kyc.active, residency.eu, or the provided topic string.
Return only the structured object.

User:

chainId: {chainId}
subject: {subject}
issuer: {issuer}
topic_hint: {topic}
expiresAt_unix: {expiresAt}
revoked: {revoked}
evidence:
---
{evidence_body}
---
raw event: {decoded_event_json}

Response model: NormalizedClaim minus chain-assigned ids (you overwrite claimId, txHash, blockNumber after). Temperature 0. Max tokens 800. Timeout 8s.

P2 — Explain fused state

System:

You write short, specific trust explanations for a relying party.
You do not compute a new score. The numbers in the user message are authoritative.
Cite feature names exactly as given. If SHAP and the fusion residual disagree, say so.
Name the conflict type: multi-source | stale | self-contradiction | none.
No marketing language. No "as an AI".
Output the structured object only.

User:

subject: {subjectDid}
verdict: {verdict}
confidence: {confidence}
scoreBps: {scoreBps}
topics: {topics_json}
conflicts: {conflicts_json}
per_claim: {claims_slim_json}
shap_top5: {shap_json}
issuer_priors: {beta_json}
fusion_note: {e.g. "cumulative ⊕ then conflict penalty"}

Response model:

class Reason(BaseModel):
    feature: str
    shap: float | None
    text: str

class Explanation(BaseModel):
    summary: str
    reasons: list[Reason]
    caveats: list[str]
    conflictType: Literal["multi-source","stale","self-contradiction","none"]

Temperature 0.2. Max tokens 500. Timeout 10s.

P3 / P4 — CRAVE dual perspective (optional)

From CRAVE (arXiv:2504.14905). Two calls, then a local merge. Do not fine-tune a judge.

P3 system: “Argue that the claim is authentic. Cover: (1) direct evidence, (2) semantic relations, (3) linguistic patterns, (4) logic. Cite only the provided evidence. If you cannot, say you cannot.”

P4 system: same axes, argue the claim is inauthentic or stale.

Local merge (Python, not an LLM if you want purity): if P3 is empty and P4 is rich, add a caveat “support perspective found no evidence.” Feed both strings into P2 as extra context. The official score still comes from sklearn + fusion.

Conflict types (CONFLICTS / DRAGged 2025)

  • multi-source — two issuers, opposite polarity, both unexpired.
  • stale — newer claim vs expired/revoked older one; should usually not remain a conflict after features.
  • self-contradiction — same issuer, opposite polarity, no revoke.
  • none — fused cleanly.

Rules fallback (must exist)

If evidence is JSON with keys topic, polarity, expiresAt, copy them. If it is empty, use event fields only. rawText becomes "". signatureValid true for ClaimSource. This path must satisfy FR-02 on the inline fixture.

Explanation template fallback

summary = f"{verdict} on {n} claims. confidence={confidence:.2f}."
reasons = [Reason(feature=name, shap=val, text=f"{name} contributed {val:+.3f}.") for name,val in shap_top5]
caveats = ["Templated explanation; LLM unavailable.", "Score from sklearn+subjective-logic."]

Anti-patterns

  • “Rate this claim 1–5.” (TrustJudge: coarse scores collide.)
  • Asking the model to pick a winner without listing both sides.
  • Feeding the whole training set into the prompt.
  • LangChain clouds that log PII evidence to a third party without saying so. Prefer local or a known LLM_BASE_URL.
