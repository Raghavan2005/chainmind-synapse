DevOps — linked, gated, cheap

The product is a Vite dashboard on Vercel (Hobby) plus a Python brain that stays on a laptop, Codespaces, or Compose until a human explicitly pays for AWS compute. GitHub Actions is the coupler: CI always runs; image push and Vercel-from-Actions stay behind repository variables. Overlay JSON is a cache. The ledger is the record. No hosted database.

Vercel = dashboard only AWS default = OIDC + ECR App Runner held No RDS · no NAT · no always-on 1 vCPU

Install and identity (already used on this workstation): vercel --version ≥ 54, vercel whoami. Scope is the logged-in team, not a second Vercel org “for AWS.”

IAM hygiene (defensive only)

  • Prefer OIDC short-lived creds. A leaked AKIA in this repo is an incident; rotate and delete, do not “also add it to Actions so deploy works.”
  • GHA role: ecr:GetAuthorizationToken on * (AWS requires that) and push/describe on this one repository ARN. Nothing else.
  • Never attach AdministratorAccess to chainmind-synapse-gha.
  • App Runner instance role, if created, gets secretsmanager:GetSecretValue on one ARN. No kms:* wildcards.
  • Frontend bundles are public. Treat every VITE_* as already published.
  • Do not debug hosted IAM by curling instance metadata from the API. There is no reason for this app to reach 169.254.169.254.

CORS, BYOK, and a public origin

  1. Local Vite proxies /v1 → 127.0.0.1:8000. No CORS needed on that path.
  2. Vercel production is a different origin. The API must allow it. Default CORS_ORIGINS=* keeps the hackathon moving and is workstation-demo only once BYOK keys are in play.
  3. When the API is on a tunnel or App Runner: CORS_ORIGINS=https://chainmind-synapse.vercel.app,https://*.vercel.app (or the exact preview host). FastAPI does not treat a wildcard inside a comma list as a glob — list concrete origins you care about, or keep * for the live demo and say so out loud.
  4. GET /v1/identity never calls the LLM. A public API does not need an operator LLM key.
